## What This Repo Is

`docs/` is the **public documentation website** for AskAide AI, built with [Docusaurus](https://docusaurus.io/) 3 (React 19). It is a **static site** — no application logic, and no access to the product, backend, or database. It documents the product implemented by the sibling repos; nothing here runs in production beyond serving static HTML.

- Site title: `AskAide AI Docs`
- Served at `https://askaide-ai.github.io` under base URL `/docs/`
- Deploys via **GitHub Actions** (`.github/workflows/deploy.yml`: push to `main` → `npm ci` → `npm run build` → `actions/deploy-pages@v4`). There is **no `gh-pages` branch** and `docusaurus deploy` is not used.
- Blog is disabled; docs are served at the site root (`routeBasePath: '/'`)

## Commands

This repo uses **npm** (lockfile is `package-lock.json`; there is no `yarn.lock`).

```bash
npm install          # Install dependencies
npm start            # Local dev server with live reload (runs prestart gates)
npm run build        # Prebuild gates → static site into build/ → postbuild redirect check
npm run serve        # Serve the built site locally (docusaurus serve)
npm run sync:contracts   # Regenerate docs/shared-contracts/api-definitions.md from ../shared-contracts
npm run check:contracts  # The contract-sync drift gate on its own
```

Other scripts: `npm run clear` (clear cache), `npm run swizzle` (eject/override theme components).

`npm run deploy` (docusaurus deploy) is legacy — deployment goes through GitHub Actions only.

## Layout

| Path | Purpose |
|------|---------|
| `docs/` | Markdown/MDX documentation content — the actual pages. Top-level sections: `frontend/`, `backend/`, `ai-service/`, `shared-contracts/`, `reference/`, `learning-resources/`, plus `intro.md` |
| `src/` | Custom theme code — `pages/` (React pages, e.g. the homepage), `components/` (e.g. `HomepageFeatures`), `css/custom.css` |
| `static/` | Assets served as-is (`img/`, favicon, logo, robots.txt) — referenced assets only; delete an asset in the same change that orphans it |
| `scripts/` | Build gates + the contract mirror generator (`sync-contracts.mjs`, `check-*.mjs`) |
| `docusaurus.config.js` | Site config — title, tagline, URL/baseUrl, navbar, footer, redirect table wiring, deploy settings |
| `sidebars.js` | Documentation sidebar structure (maps doc IDs into the nav tree), hand-maintained |
| `build/` | Generated output — **never hand-edit**; regenerated by `npm run build` |

## Build gates (fail the build — that is the point)

- `scripts/check-contracts-sync.mjs` — the shared-contracts mirror must byte-match a fresh regeneration from `../shared-contracts` (skipped in CI by design: the canonical lives in a separate repo).
- `scripts/check-docs-consistency.mjs` — every file in `docs/` has a `sidebars.js` row and every id resolves; no duplicates.
- `scripts/check-docs-meta.mjs` — every content page carries `title` / `description` / `sidebar_position` frontmatter.
- `scripts/check-redirects.mjs` (postbuild) — every retired path in `scripts/lib/retired-redirects.mjs` produced a redirect stub in `build/`. The redirects plugin silently drops redirects that would override an existing route; this gate makes that loud.
- `onBrokenLinks: 'throw'` — a link to a page that does not exist fails the build.

## Content conventions

**Folder rules**

- `docs/` root holds only `intro.md` (site landing). A new top-level section must bring a landing doc and a navbar/footer decision in the same change.
- `docs/{frontend,backend,ai-service}/` — exactly one `overview.md` landing per service (navbar target); children are `architecture.md`, `lld.md`, and the family folders below. Tree depth never exceeds service/family/file.
- `docs/{service}/product/` — why we built it, project status, roadmap. No endpoint tables, no run instructions.
- `docs/{service}/features/` — behavior of **shipped** features (flows, contracts-as-behavior, catalogs). Proposed-but-unbuilt designs never enter this repo.
- `docs/{service}/development/` — contributing to that service: setup, conventions, testing, deployment, troubleshooting, changelog. Per-feature API references belong in `reference/`.
- `docs/{service}/reference/` — frozen reference extracted from code (endpoint catalogs, schemas, system design). Each page states what it reflects and is corrected or re-dated when the code moves. No third rendering of a schema that exists elsewhere.
- `docs/shared-contracts/` — landing + generated mirror only; no subfolders.
- `docs/reference/` — **cross-service** material only (hld, getting-started, user-guide, api-reference, developer-guide, integration). Anything about one service lives under that service. Never cite agent-instruction files (CLAUDE.md) as reader content.
- `docs/learning-resources/` — newcomer tutorials; every pointer must resolve inside the public site (site URLs only — no workspace paths, drive letters, or repo files).
- `src/pages/` — real site pages only; template leftovers are deleted on sight.

**Frontmatter standard** — every hand-maintained page starts with `---` frontmatter: `title` identical to the page's H1 (≤60 chars), `description` 120–155 chars saying what the page is for, `sidebar_position` integers with gaps of 10 following the `sidebars.js` order (so nav order is provably unchanged).

**Generated mirror** — `docs/shared-contracts/api-definitions.md` is generated by `scripts/sync-contracts.mjs`. **Never hand-edit it** — edit the canonical in `../shared-contracts/api-definitions.md` and run `npm run sync:contracts`. `api-definitions.sync.json` records the source hash and sync time.

**Public guardrails** — no pricing, sales/funding strategy, or internal-audit content; no private-repo paths or internal-docs references (say "the team's private documentation"); no credentials, service-account keys, or machine paths; no AI-chat artifacts; engineering standards stay in the owning repos. Public pages link the public `/pricing` route instead of describing pricing.

**Retiring a page** — requires rewriting **every reference to it in the same PR** (markdown links AND inline-code mentions — inline mentions are invisible to `onBrokenLinks`), adding the old path to `scripts/lib/retired-redirects.mjs` (base-URL-relative: `/frontend/…`, never `/docs/…`), and removing its `sidebars.js` row.

## Guardrails

1. **This site is public.** Never add pricing, sales scripts, funding strategy, credentials, internal audits, or any `../internal-docs/` content here. Public/private separation is deliberate.
2. **Don't hand-edit `build/`** — it is generated. Edit sources in `docs/` / `src/` and rebuild.
3. Keep content in sync with actual product behavior; stale docs mislead users and hurt SEO.
4. **Never hand-edit the generated mirror** — `docs/shared-contracts/api-definitions.md` (see Content conventions).

## Cross-Repo Context

Sibling repos live alongside this one under the monorepo checkout (`../` from this repo): `frontend/`, `backend/`, `ai-service/`, `shared-contracts/`, and the private `internal-docs/`. This site documents the product those repos implement — when a user-facing feature changes there, the relevant page here may need updating. `CLAUDE.md` in this repo is a one-line pointer to this file — edit **this** file, never the pointer.
